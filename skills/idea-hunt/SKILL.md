---
name: idea-hunt
description: Find a real, painful, niche problem worth solving. Use when the user wants a product/side-project idea or has a vague domain. Not for judging an existing idea (use idea-validate).
---

# Goal
One specific, painful problem for one specific group. Problem first — never start from a solution or a technology.

# Steps
1. Ask, one question at a time: what world does the user know deeply, what is slow/expensive/annoying there, what unfair advantage do they have.
2. Search for evidence of pain:
   - Workarounds (spreadsheets, group chats, manual labor) = strongest signal
   - Complaints (Reddit, 1–2★ reviews, forums)
   - People paying for a bad solution
3. Invert: who do current solutions ignore? What just changed (law, tech, behavior)?
4. Write 3–5 problem statements: "[group] struggles with [task] because [cause]. Today they [workaround], costing [time/money]."
5. Score each 1–5: pain, frequency, willingness to pay, user's advantage. The user picks — not you.

# Rules
- No evidence → say "no evidence yet". Never invent pain, never praise.
- Nice-to-have is not pain.
